# 試算表結構（收銀資料庫）

> 📎 當天實際使用的試算表（唯讀）：<https://docs.google.com/spreadsheets/d/10L4bqqWCrQ6Pg7V77s9D2CnnGREZXjdDYWMLO1psx5E/edit?usp=sharing>　人員信箱已替換為 `hi@pg72.tw`。

整份系統只用一份 Google 試算表當資料庫，Apps Script 綁定在這份試算表上（`SpreadsheetApp.getActiveSpreadsheet()`），所以程式裡沒有寫死試算表 ID。

| 工作表 | 用途 | 誰會寫入 |
|---|---|---|
| `菜單` | 品項、價格、庫存、套餐配方 | 人工維護；`submitOrder` 扣庫存 |
| `訂單` | 訂單總表，一列一張訂單 | `submitOrder` 新增、`updateOrderStatus` / `markOrderPickedUp` 改狀態 |
| `Order#0` | 訂單範本（隱藏） | 人工維護 |
| `Order#1…N` | 每張訂單一份，複製自 `Order#0` | `submitOrder` 建立、KDS / Pickup 更新旗標 |

工作表名稱寫在 `Code.js` 開頭的常數裡（`MENU_SHEET`、`ORDER_SUMMARY_SHEET`、`TEMPLATE_SHEET`），改名時兩邊要一起改。

## `菜單`

### A–D 欄：品項

| 欄 | 標題 | 說明 |
|---|---|---|
| A | 類別 | `套餐`、`關東煮`、`飲料`。**「關東煮」和「套餐」會送到關東煮 KDS，「飲料」送到飲料 KDS** |
| B | 品名 | 必須唯一，配方與訂單都用品名對應 |
| C | 價格 | 數字；空白或 0 的列不會出現在 POS。E 餐依這欄分組（15 / 20 / 25） |
| D | 庫存 | 整數，`submitOrder` 會直接改寫這欄。套餐列留空（可售數量由配方算出） |

### E 欄之後：套餐配方

程式從 **E 欄起**讀取：第 1 列是套餐名稱（必須和 B 欄的套餐品名完全一致），往下是組成品項的品名。標題空白的欄會被略過。

- **固定套餐**：往下列出品名，例如 `蘿蔔`、`王子麵`、`玉米`。
- **E 餐**：往下寫 `15`、`20`、`25`，程式看到第一格是 `"15"` 就當成三選一套餐。
- **G 餐**：不需要配方，程式用品名 `G餐-內用吃到飽` 判斷。

> 當天的試算表在 E 欄放了一欄沒有標題的數字（關東煮與飲料為 50–80），看起來是備料量的紀錄。因為標題空白，程式不會讀它，配方實際從 F 欄開始。

## `訂單`（總表）

| 欄 | 當天標題 | `setup()` 建立的標題 | 內容 |
|---|---|---|---|
| A | 訂單編號 | 訂單ID | `Order#N`，與明細工作表同名 |
| B | 取餐號碼 | 取餐號碼 | 每天從 1 開始 |
| C | 時間 | 時間戳記 | 送單時間 |
| D | 品名 | 項目 (JSON) | POS 送出的完整 `orderData` JSON 字串 |
| E | 價錢 | 總金額 | `orderData.total` |
| F | 狀態 | 狀態 | `pending` → `preparing` → `ready_for_pickup` → `completed` |
| G | 點餐人員 | 收銀員 | `Session.getActiveUser().getEmail()` |

程式只用欄位**位置**讀寫，所以標題可以自由改名（當天就和 `setup()` 的預設不同），但**欄位順序不能動**。KDS 和 OCS 的查詢都是讀這張表，D 欄的 JSON 是 KDS 顯示品項的唯一來源。

## `Order#0`（範本）與 `Order#N`（訂單明細）

### A–B 欄：訂單資訊與狀態旗標

| 列 | A 欄 | B 欄內容 |
|---|---|---|
| 2 | 訂單確認時間 | 送單的完整時間（取餐號碼每日重置就是讀這格的日期） |
| 3 | 取餐號碼 | |
| 4 | 時間 | `HH:mm:ss` |
| 5 | 總金額 | |
| 6 | 收銀員 | |
| 7 | 關東煮接單 | `1`＝待接單 |
| 8 | 飲料接單 | `1`＝待接單 |
| 9 | 關東煮準備中 | `1`＝製作中 |
| 10 | 飲料準備中 | `1`＝製作中 |
| 11 | 關東煮完成 | `1`＝完成 |
| 12 | 飲料完成 | `1`＝完成 |
| 13 | 已取餐 | `1`＝顧客已取餐 |

**列號是寫死在程式裡的**，範本不能在這個區塊插入或刪除列。

### C–F 欄：品項明細

範本預先列好所有品項（類別、品名、空白數量、價格），送單時只在 E 欄「數量」填上點的份數。E 餐的總份數填在「E餐-1+1+1」那一列。

> 只有範本裡**已經列出**的品名會被寫入數量。菜單新增品項時要記得同步加進 `Order#0`，否則該品項只會留在總表的 JSON 裡，明細表看不到。

### G–I 欄：E 餐內容

`套餐E-15`、`套餐E-20`、`套餐E-25`，每份 E 餐寫一列。

### 當天範本的其他欄位

當天的 `Order#0` 另外有「果汁口味」「果汁」兩欄（口味選項：蘋果、檸檬、百香果），以及 A–F 餐配方的對照欄。這些欄位程式不會讀寫，應該是給現場人員參考用的。
